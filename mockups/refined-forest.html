Overview

Pipelining lets multiple instructions occupy the processor at once, each at a different stage. Instead of finishing one instruction before starting the next, a pipelined processor overlaps them to raise throughput.

Without pipelining: each instruction takes five clock cycles and the next waits for all five. Five instructions cost 25 cycles.

With pipelining: while instruction 1 decodes, instruction 2 fetches. Five instructions cost 9 cycles — five to fill, four to drain. Once full, one instruction retires per cycle.

Pipeline stages

StageNameWork performed
IFInstruction fetchRead the instruction at PC; increment PC
IDInstruction decodeDecode opcode; read register operands
EXExecuteALU operation, branch target calculation
MEMMemory accessLoad from or store to data memory
WBWrite backWrite the result into the register file

Pipeline registers

Between each pair of stages sits a register that latches the working set forward on the clock edge. These are what make the stages independent.

// IF/ID pipeline register - latches instruction and PC
module if_id_reg (
    input         clock, reset, enable,
    input  [31:0] instr_in, pc_in,
    output [31:0] instr_out, pc_out
);
    register #(32) instr_r (clock, reset, enable, instr_in, instr_out);
    register #(32) pc_r    (clock, reset, enable, pc_in,    pc_out);
endmodule

The enable line is what makes stalling possible: hold it low and the stage freezes while the rest of the pipeline drains.
