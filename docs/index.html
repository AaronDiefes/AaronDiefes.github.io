Architecture Overview

What is this engine?

This is a 2D graphics rendering engine built from scratch in C++. It takes high-level drawing commands (like "draw a rectangle" or "fill a path with a gradient") and produces the actual pixel colors you see on screen.

The engine implements a subset of functionality found in production libraries like Skia (used by Chrome and Android) and Cairo. It includes shape drawing, matrix transformations, shader systems, path rendering, and Porter-Duff alpha blending.

How does C++ run in the browser?

The engine is compiled to WebAssembly (WASM) using Emscripten. WebAssembly is a low-level bytecode format that runs in modern browsers at near-native speed. This means the same C++ code that would render on a desktop runs directly in your browser—no server required.

Build Command (from Makefile.wasm):

# Compile C++ to WebAssembly
emcc -std=c++17 -O3 \
     --bind \
     -s WASM=1 \
     -s ALLOW_MEMORY_GROWTH=1 \
     -s MODULARIZE=1 \
     my_canvas.cpp wasm_bindings.cpp \
     -o graphics_engine.js

This produces two files: graphics_engine.wasm (132KB of compiled C++ code) and graphics_engine.js (the JavaScript glue code to load and interact with the WASM module).

How JavaScript and WASM communicate

Emscripten provides EMSCRIPTEN_BINDINGS to expose C++ classes and functions to JavaScript. This creates a bridge between the WASM module and the browser's JavaScript environment.

Example Bindings (from wasm_bindings.cpp):

EMSCRIPTEN_BINDINGS(graphics_engine) {
    // Expose Canvas API
    class_<CanvasWrapper>("CanvasWrapper")
        .constructor<int, int>()
        .function("drawRect", &CanvasWrapper::drawRect)
        .function("save", &CanvasWrapper::save)
        .function("restore", &CanvasWrapper::restore)
        .function("translate", &CanvasWrapper::translate);

    // Expose Shader factories
    function("createLinearGradient", &createLinearGradient);
    function("createBitmapShaderFromFile", &createBitmapShaderFromFile);

    // Expose enums
    enum_<GBlendMode>("BlendMode")
        .value("SrcOver", GBlendMode::kSrcOver)
        .value("Xor", GBlendMode::kXor);
}

Once the WASM module is loaded, JavaScript can call these functions directly. For rendering, the pixel buffer is transferred from WASM memory to an HTML5 Canvas using ImageData. The engine writes ARGB pixels, which are converted to RGBA and displayed at 60fps.
