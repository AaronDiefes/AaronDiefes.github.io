Introduction

The 2D graphics engine is built on a layered architecture where high-level drawing commands flow through a series of transformations before becoming pixels on screen. Understanding this architecture is essential for navigating the codebase and extending the engine with new features.

This page provides visual diagrams explaining the core systems: the rendering pipeline, canvas abstraction, shader hierarchy, transformation stack, and blend pipeline. Each diagram shows how components interact and where data flows through the system.

1. Rendering Pipeline

Every draw call—whether drawRect(), drawPolygon(), or drawPath()—flows through this pipeline. The high-level command is transformed into a list of edges, clipped to the viewport, rasterized into pixels, shaded with colors, and composited onto the framebuffer using blend modes.

The rendering pipeline consists of seven stages:

  1. Draw Call: High-level API function (drawRect, drawPolygon, drawPath)
  2. Transform: Apply current transform matrix (CTM) to shape vertices
  3. Clip: Clip shape to viewport boundaries
  4. Rasterize: Convert edges to pixel coordinates via scanline algorithm
  5. Shade: Compute pixel color using shader (solid, gradient, or bitmap)
  6. Blend: Composite source color with destination using Porter-Duff blend mode
  7. Pixels: Write final color to framebuffer

Key Implementation Files:

  • my_canvas.cpp - Canvas API and draw call implementations
  • Edge.h - Edge structure for scanline rasterization
  • blend_functions.h - Porter-Duff blend mode implementations
  • shader_ops.h - Shader base class and gradient implementations

2. Canvas Abstraction

The GCanvas abstract class defines the public API. The MyCanvas implementation maintains the framebuffer bitmap, CTM stack, and shader state. All drawing operations eventually call blitRow() to write scanlines.

The canvas architecture consists of:

  • GCanvas (interface): Abstract base class defining public API methods like drawRect, drawPolygon, drawPath, drawMesh, save, restore, concat
  • MyCanvas (implementation): Concrete implementation maintaining framebuffer (GBitmap fDevice), CTM stack (std::stack<GMatrix>), and implementing drawing algorithms
  • Paint: Encapsulates drawing state including shader pointer, blend mode, and fallback color

MyCanvas uses Paint for every draw operation, calling shader and blend functions to produce final pixel colors.

The blitRow() function is the core rendering primitive. It takes a Y coordinate and X range, samples the shader across that range, and blends each pixel into the framebuffer using the specified blend mode.

3. Shader System

Shaders compute pixel colors. The GShader abstract class defines the interface. Subclasses implement solid colors, linear gradients, radial gradients, sweep gradients, bitmap textures, and shader composition. Each shader implements shadeRow() to fill a scanline of colors.

The shader hierarchy consists of:

  • GShader (abstract base): Defines shadeRow() interface for filling scanlines with colors
  • SolidColorShader: Fills entire row with single color
  • LinearGradientShader: Linear interpolation between color stops
  • RadialGradientShader: Color based on distance from center point
  • AngleGradientShader (Sweep): Color based on angle using atan2
  • BitmapShader: Samples texels from bitmap with tile modes (Clamp, Repeat, Mirror)
  • ProxyShader: Applies transformation matrix before delegating to another shader
  • ComposeShader: Combines two shaders (e.g., gradient + texture)

4. Transformation Stack

The Current Transform Matrix (CTM) stack allows hierarchical transformations. Calling save() pushes the current matrix, concat() multiplies a transformation, and restore() pops back to the saved state. This enables nested transformations like rotating a shape around its center.

Text Alternative

The transformation stack workflow:

  1. save(): Application calls save(), Canvas pushes current CTM onto stack
  2. concat(Translate): Application concatenates translation, Canvas multiplies top of stack
  3. concat(Rotate): Application concatenates rotation, Canvas multiplies again (T * R)
  4. drawRect(): Application draws shape, Canvas applies combined transformation to vertices
  5. restore(): Application restores state, Canvas pops stack back to saved matrix

This pattern enables complex hierarchical transformations while keeping the API simple.

Matrix Operations: 

// GMatrix provides these operations
GMatrix::Translate(float tx, float ty)
GMatrix::Rotate(float radians)
GMatrix::Scale(float sx, float sy)

// CTM stack operations in MyCanvas
void save() {
    CTMStack.push(CTMStack.top());
}

void restore() {
    CTMStack.pop();
}

void concat(const GMatrix& matrix) {
    CTMStack.top() = CTMStack.top() * matrix;
}

5. Blend Pipeline

The Porter-Duff blend modes control how source pixels (from the shader) composite with destination pixels (existing framebuffer). Each mode uses different formulas involving source/destination colors and alpha values. The engine implements 12 standard blend modes.

Blend Mode Formula Use Case
kClear 0 Clear to transparent
kSrc S Replace destination
kDst D Keep destination
kSrcOver S + D(1-Sa) Normal alpha blending
kDstOver D + S(1-Da) Draw behind existing
kSrcIn S * Da Mask with destination
kDstIn D * Sa Keep destination inside source
kSrcOut S * (1-Da) Source outside destination
kDstOut D * (1-Sa) Destination outside source
kSrcATop S*Da + D(1-Sa) Source atop destination
kDstATop D*Sa + S(1-Da) Destination atop source
kXor S(1-Da) + D(1-Sa) Exclusive or

Visual Representation: The blend pipeline takes source RGBA and destination RGBA, applies the blend formula, and produces the final RGBA written to the framebuffer.

The blend pipeline consists of three stages:

  1. Source RGBA: Color computed by shader for the current pixel
  2. Destination RGBA: Existing color in framebuffer at that pixel location
  3. Blend Mode: Mathematical formula that combines source and destination (e.g., kSrcOver = S + D(1-Sa))
  4. Blended RGBA: Final color written back to framebuffer

All colors use premultiplied alpha, where RGB channels are already multiplied by the alpha value.

Implementation: 

// blend_functions.h
inline GPixel blend_srcover(GPixel src, GPixel dst) {
    // S + D(1-Sa)
    unsigned srcA = GPixel_GetA(src);
    unsigned invAlpha = 255 - srcA;
    return src + blend_with_alpha(dst, invAlpha);
}

// blitRow calls blend function for each pixel
void MyCanvas::blitRow(int y, int xL, int xR, const GPaint& paint) {
    GPixel row[xR - xL];
    fShader->shadeRow(xL, y, xR - xL, row);

    GPixel* dstRow = fDevice.getAddr(xL, y);
    for (int i = 0; i < xR - xL; i++) {
        dstRow[i] = blendFunc(row[i], dstRow[i]);
    }
}

Summary

These five systems work together to transform high-level drawing commands into pixels:

  • Rendering Pipeline: The flow from draw call to pixels
  • Canvas Abstraction: Public API and framebuffer management
  • Shader System: Hierarchical color computation
  • Transformation Stack: Matrix-based coordinate transformations
  • Blend Pipeline: Porter-Duff compositing formulas

For detailed implementation explanations and C++ code, explore the PA-based documentation pages covering each component.
