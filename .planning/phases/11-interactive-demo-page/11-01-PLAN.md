  <action>
Create two new visualization components following the existing RegisterView/BlockDiagramView patterns (IIFE wrapper, window export, render(state) method).

**MemoryView (memory-view.js):**
- Class MemoryView with constructor(container) that creates a table layout inside the container
- render(state) method that:
  - Reads state.memory (Uint32Array, 256 words) and state.changedMemory (Set)
  - Filters to show only non-zero memory addresses (do NOT render all 256 rows)
  - Shows empty state message "No memory addresses in use" when all zeros
  - For each non-zero address: display byte address (wordIndex * 4) in hex (0x00000028 format), value in hex (0x0000001E format), and decimal value
  - Adds CSS class 'changed' to rows where state.changedMemory.has(wordIndex)
- Table structure: `<table class="memory-table">` with thead (Address | Hex Value | Decimal) and tbody
- Use helper function formatHex32(value) for consistent hex formatting: `'0x' + (value >>> 0).toString(16).padStart(8, '0').toUpperCase()`
- Container gets class 'memory-view', includes h3 "Data Memory" heading
- Export as window.MemoryView via IIFE pattern

**InstructionView (instruction-view.js):**
- Class InstructionView with constructor(container) that creates layout inside container
- render(state) method that:
  - Determines current instruction from state.pipeline.IF.instruction (Phase 10 decision: always read from IF.instruction regardless of active stage in non-pipelined mode)
  - Determines active stage by checking which stage has active=true (WB > MEM > EX > ID > IF priority)
  - If no instruction active: show "No instruction active" placeholder
  - If instruction active: show mnemonic with stage label (e.g., "ADD (EX stage)")
  - Show instruction fields based on InstructionSet.get(mnemonic).fields:
    - Opcode (always): the mnemonic string
    - rs (if definition.fields.rs): "$N" format
    - rt (if definition.fields.rt): "$N" format
    - rd (if definition.fields.rd): "$N" format
    - immediate (if definition.fields.immediate): decimal and hex
  - Show instruction comment if present (instruction.comment)
- Container gets class 'instruction-view', includes h3 "Current Instruction" heading
- Use CSS classes: .instruction-display, .instruction-mnemonic, .instruction-fields, .field, .field-name, .field-value, .instruction-comment
- Export as window.InstructionView via IIFE pattern

**Important:** Do NOT use innerHTML for the render() hot path on full table rewrites when a simple DOM update would suffice. However, since memory rows change dynamically (different addresses become non-zero), innerHTML on the tbody is acceptable and matches the RegisterView pattern.
  </action>

Create the InstructionList component and add CSS styles for all three new components.

**InstructionList (instruction-list.js):**
- Class InstructionList with constructor(container, engine) where engine is an AnimationEngine instance
- loadProgram(program, frameSequence) method that:
  - Stores program.instructions reference
  - Builds instruction-to-frame map by scanning frameSequence.frames: for each frame where frame.pipeline.IF.active is true, record the first frame index for each unique PC value (pc / 4 = instruction index). Use Map: instructionIndex -> frameIndex. Only record first IF frame per instruction index.
  - Renders an ordered list (`<ol class="instruction-list">`) of program instructions
  - Each `<li class="instruction-item">` shows: mnemonic, operands ($rd, $rs, $rt, immediate as applicable), and comment if present
  - Items with valid frame mappings get tabindex="0" for keyboard accessibility
  - Wire click handlers: on click, call this.engine.jumpToFrame(frameIndex) with the mapped frame index
  - Wire keyboard handlers: Enter or Space on focused item also calls jumpToFrame
- Private method _updateCurrentInstruction() called on 'cpu:framechange' event:
  - Reads engine.getCurrentState() to find which instruction is currently in IF stage
  - Adds 'active' class to the corresponding list item, removes from all others
  - Auto-scrolls active item into view with scrollIntoView({ behavior: 'smooth', block: 'nearest' }) - but ONLY when engine is NOT playing (check engine.isPlaying to avoid scroll jank during playback)
- Private method _formatOperands(instruction) that formats register and immediate fields
- Container gets class 'instruction-list-container', includes h3 "Program Instructions"
- Listen to window 'cpu:framechange' event in constructor to call _updateCurrentInstruction
- Export as window.InstructionList via IIFE pattern
