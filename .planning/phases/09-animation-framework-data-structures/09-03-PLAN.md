  <files>cpu-simulator/src/core/sequence-generator.js</files>
  <action>
Create `sequence-generator.js` in `cpu-simulator/src/core/`.

Implement a `SequenceGenerator` class that generates an array of CPUState snapshots from a list of instructions. This is a NON-PIPELINED simulation for Phase 9 -- each instruction completes all 5 stages before the next begins. Pipelining (where multiple instructions overlap in different stages) is Phase 12 territory.

**Why non-pipelined first:** Educational progression. Users learn what each pipeline stage does with single-instruction execution before seeing pipelining overlap. The frame structure supports pipelining later (each stage has an `active` flag and can hold its own instruction).

**Static method: `generateSequence(instructions, initialState = null)`**

Returns `{ frames: CPUState[], instructions: instruction[], metadata: { totalCycles, totalInstructions } }`.

Algorithm:
1. Create initial state via `CPUState.createInitial()` (or use provided initialState)
2. Push initial state as frame 0
3. For each instruction in the list:
   a. **IF stage frame**: Clone current state. Set `pipeline.IF.instruction = instruction`, `pipeline.IF.pc = state.pc`, `pipeline.IF.active = true`. Clear other stages' `active` flags. Increment `cycleCount`. Clear `changedRegisters` and `changedMemory` sets. Push cloned state.
   b. **ID stage frame**: Clone previous. Move instruction to ID stage: set `pipeline.ID.instruction = instruction`, decode fields (`pipeline.ID.opcode = instruction.mnemonic`, `pipeline.ID.rs = instruction.rs`, `pipeline.ID.rt = instruction.rt`, `pipeline.ID.rd = instruction.rd || instruction.rt`, `pipeline.ID.imm = instruction.immediate || 0`). Read register values: `pipeline.ID.rsVal = state.getRegister(instruction.rs || 0)`, `pipeline.ID.rtVal = state.getRegister(instruction.rt || 0)`. Set ID active, IF inactive. Increment `cycleCount`. Push.
   c. **EX stage frame**: Clone previous. Call `InstructionSet.get(instruction.mnemonic).execute(state, instruction)` to get ALU results. Store results in `pipeline.EX`: `aluResult`, `writeData`, `writeReg`, `zero` (for branches), `active = true`. Set ID inactive. Increment `cycleCount`. Push.
   d. **MEM stage frame**: Clone previous. If instruction is LW: read from memory using `state.getMemory(pipeline.EX.aluResult)`, store in `pipeline.MEM.memData`. Set `pipeline.MEM.memRead = true`. If instruction is SW: write to memory using `state.setMemory(pipeline.EX.aluResult, pipeline.ID.rtVal)`, add address to `changedMemory`. Set `pipeline.MEM.memWrite = true`. Copy EX results to MEM stage fields. Set MEM active, EX inactive. Increment `cycleCount`. Push.
   e. **WB stage frame**: Clone previous. If instruction writes to register (ADD, SUB, ADDI, LW): write result to register file using `state.setRegister()`. For LW, write `pipeline.MEM.memData`; for others, write `pipeline.MEM.writeData`. Set `pipeline.WB.regWrite = true` for write-back instructions. Update PC: normal instructions `pc += 4`; BEQ (if zero flag true) `pc = branchTarget`; J `pc = jumpTarget`. Increment `instructionCount`. Set WB active, MEM inactive. Increment `cycleCount`. Push.
4. Return frames array with metadata

**Important implementation details:**
- The execute function from InstructionSet returns computed values -- it does NOT mutate the state. The SequenceGenerator applies those values to the appropriate pipeline stage.
- For BEQ: if the branch is NOT taken, PC still advances by 4. If taken, PC jumps to `pc + immediate * 4` (relative offset from current instruction's PC, not from current state.pc). Store the branch target during EX and apply in WB.
- For J: PC becomes `immediate * 4` (the absolute word address). Store during EX, apply in WB.
- Register $0 protection: always use `state.setRegister()` which enforces $0 = 0.
- Each frame's `changedRegisters` and `changedMemory` should reflect what changed in THAT stage only. Clear these sets at the start of each stage frame (except WB where changes happen).
- `activeStages` set should contain only the currently active stage name for clear visualization.

**Static method: `generateSequenceAsync(instructions, initialState, onProgress)`**

Same as generateSequence but uses chunked generation with yielding (per research recommendation). Processes 10 instructions at a time, yields to browser between chunks via `setTimeout(resolve, 0)`. Calls `onProgress(percent)` after each chunk. Returns a Promise.

This is for future use with longer programs. For Phase 9's short programs (< 20 instructions), synchronous generation is fine, but having the async version ready prevents Phase 11 from needing to refactor.

Export via `window.SequenceGenerator = SequenceGenerator;`. Wrap in IIFE.

**basic-instructions.js:**

Define `BASIC_PROGRAM` object:
```javascript
{
  name: "Basic Instructions Walkthrough",
  description: "Demonstrates all 8 core RISC instruction types: register arithmetic, immediates, memory load/store, branch, and jump.",
  instructions: [
    // Step 1: Load immediate values into registers
    ADDI $8, $0, 10       // $8 = 0 + 10 = 10
    ADDI $9, $0, 20       // $9 = 0 + 20 = 20

    // Step 2: Register arithmetic
    ADD  $10, $8, $9      // $10 = $8 + $9 = 30
    SUB  $11, $9, $8      // $11 = $9 - $8 = 10

    // Step 3: Memory operations
    SW   $10, 0($8)       // mem[10] = $10 = 30  (store word)
    LW   $12, 0($8)       // $12 = mem[10] = 30  (load word)

    // Step 4: Branch (taken)
    BEQ  $8, $8, 2        // $8 == $8 is true, skip 2 instructions ahead (jump over NOP to J)

    // Step 5: NOP (skipped by branch)
    NOP                   // This gets skipped

    // Step 6: Jump back to end cleanly
    J    0                // Jump to address 0 (loops back -- demonstrates J instruction)
  ]
}
```

Build each instruction using `InstructionSet.createInstruction()`:
- `InstructionSet.createInstruction('ADDI', { rs: 0, rt: 8, immediate: 10 })`
- `InstructionSet.createInstruction('ADDI', { rs: 0, rt: 9, immediate: 20 })`
- `InstructionSet.createInstruction('ADD', { rs: 8, rt: 9, rd: 10 })`
- `InstructionSet.createInstruction('SUB', { rs: 9, rt: 8, rd: 11 })`
- `InstructionSet.createInstruction('SW', { rs: 8, rt: 10, immediate: 0 })` -- mem[rs + imm] = rt
- `InstructionSet.createInstruction('LW', { rs: 8, rt: 12, immediate: 0 })` -- rt = mem[rs + imm]
- `InstructionSet.createInstruction('BEQ', { rs: 8, rt: 8, immediate: 2 })` -- branch offset = 2
- `InstructionSet.createInstruction('NOP', {})` -- skipped by branch
- `InstructionSet.createInstruction('J', { immediate: 0 })` -- jump to address 0

Include inline comments (as `comment` field on each instruction object) explaining what each instruction does for the UI to display.

**fibonacci.js:**

Define `FIBONACCI_PROGRAM` object:
```javascript
{
  name: "Fibonacci Sequence",
  description: "Computes the first 8 Fibonacci numbers (1, 1, 2, 3, 5, 8, 13, 21) using a loop with registers and stores results in memory.",
  instructions: [
    // Initialize: fib(0)=1, fib(1)=1, counter=8, address=0
    ADDI $8, $0, 1        // $8 = 1 (current fib number = fib(0))
    ADDI $9, $0, 1        // $9 = 1 (next fib number = fib(1))
    ADDI $10, $0, 8       // $10 = 8 (loop counter -- compute 8 numbers)
    ADDI $11, $0, 0       // $11 = 0 (memory address pointer)

    // Loop body: store current, compute next, decrement counter
    SW   $8, 0($11)       // mem[$11] = $8 (store current Fibonacci number)
    ADD  $12, $8, $9      // $12 = $8 + $9 (next Fibonacci = current + next)
    ADD  $8, $9, $0       // $8 = $9 (shift: current = next)
    ADD  $9, $12, $0      // $9 = $12 (shift: next = computed)
    ADDI $11, $11, 4      // $11 = $11 + 4 (advance memory pointer by one word)
    ADDI $10, $10, -1     // $10 = $10 - 1 (decrement counter) -- use negative immediate
    BEQ  $10, $0, 1       // if counter == 0, skip to end (branch offset 1)
    J    4                // jump back to loop body (instruction at address 16 = word 4)

    // End: NOP to cleanly terminate
    NOP
  ]
}
```

Build each with `InstructionSet.createInstruction()`. Include `comment` field on each.

Export via `window.FIBONACCI_PROGRAM = FIBONACCI_PROGRAM;`.
