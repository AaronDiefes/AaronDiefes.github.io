  <name>Task 1: Create CPUState data structure with pipeline stages, registers, memory, and clone support</name>
  <files>cpu-simulator/src/core/cpu-state.js</files>
  <action>
Create the directory structure `cpu-simulator/src/core/` and the `cpu-state.js` file.

Implement a `CPUState` class with the following structure:

**Pipeline stages** (object with 5 stages):
- `IF`: `{ instruction: null, pc: 0, active: false }` -- Instruction Fetch
- `ID`: `{ instruction: null, opcode: '', rs: 0, rt: 0, rd: 0, imm: 0, rsVal: 0, rtVal: 0, active: false }` -- Instruction Decode
- `EX`: `{ aluResult: 0, writeData: 0, writeReg: 0, zero: false, active: false }` -- Execute
- `MEM`: `{ memData: 0, writeData: 0, writeReg: 0, memRead: false, memWrite: false, active: false }` -- Memory Access
- `WB`: `{ writeData: 0, writeReg: 0, regWrite: false, active: false }` -- Write Back

**Registers:**
- `registers`: `new Uint32Array(32)` -- 32 general-purpose registers (register 0 always reads as 0)

**Memory:**
- `memory`: `new Uint32Array(256)` -- 256-word data memory (1KB for demo purposes)

**Control state:**
- `pc`: `0` -- Program counter (word-aligned, increments by 4)
- `cycleCount`: `0` -- Total clock cycles executed
- `instructionCount`: `0` -- Total instructions completed (written back)

**Visualization metadata:**
- `changedRegisters`: `new Set()` -- Which registers changed this cycle (for highlighting in Phase 10)
- `changedMemory`: `new Set()` -- Which memory addresses changed this cycle
- `activeStages`: `new Set()` -- Which pipeline stages are active this cycle
- `hazards`: `[]` -- Active hazards (empty for now, forward compatibility for Phase 12)
- `stalls`: `[]` -- Active stalls (empty for now, forward compatibility for Phase 12)

**Methods:**
- `clone()`: Returns a deep copy using `structuredClone(this)`. After cloning, reconstruct `Set` objects from their serialized form since `structuredClone` handles Sets natively. Do NOT use `Object.freeze()` in production -- the research suggested it but it interferes with structuredClone on subsequent clones and adds complexity. Instead, treat snapshots as immutable by convention.
- `static createInitial()`: Factory method that returns a fresh CPUState with all defaults. Register 0 explicitly set to 0.
- `getRegister(index)`: Returns `this.registers[index]` (ensures index 0 always returns 0 by checking).
- `setRegister(index, value)`: Sets register value only if index !== 0. Adds index to `changedRegisters` if value actually changed.
- `getMemory(address)`: Returns word at `this.memory[address >> 2]` (word-aligned access).
- `setMemory(address, value)`: Sets word at `this.memory[address >> 2]`. Adds address to `changedMemory` if value changed.

Export the class using a global assignment pattern: `window.CPUState = CPUState;` (no module bundler -- vanilla JS per project decision). Wrap in an IIFE to avoid polluting global scope with internal helpers.

Do NOT use `process.env.NODE_ENV` (not available in browser). Do NOT use ES modules (no bundler). Use vanilla JS class syntax.

<task type="auto">
  <name>Task 2: Create InstructionSet with 8 core RISC instruction definitions</name>
  <files>cpu-simulator/src/core/instruction-set.js</files>
  <action>
Create `instruction-set.js` in `cpu-simulator/src/core/`.

Implement an `InstructionSet` class (or object literal) defining 8 core RISC instructions. Use simplified object representation per research recommendation (not full binary encoding -- that's for Phase 13+ documentation).

**Instruction type categories:**
- **R-type** (register-register): ADD, SUB
- **I-type** (immediate): ADDI, LW
- **S-type** (store): SW
- **B-type** (branch): BEQ
- **J-type** (jump): J
- **Special**: NOP (no operation -- simplifies pipeline bubbles)

**Each instruction definition includes:**
```javascript
{
  mnemonic: 'ADD',           // Human-readable name
  type: 'R',                 // R, I, S, B, J
  description: 'Add two registers',
  fields: {
    rs: true,                // Uses source register 1
    rt: true,                // Uses source register 2
    rd: true,                // Uses destination register
    immediate: false         // Does not use immediate value
  },
  execute: function(state, instruction) {
    // Returns the ALU result for EX stage
    // Does NOT modify state -- just computes
  }
}
```

**Instruction definitions with execute functions:**

1. **ADD** (R-type): `rd = rs + rt`. Execute returns `{ aluResult: rsVal + rtVal, writeReg: rd, writeData: rsVal + rtVal }`.
2. **SUB** (R-type): `rd = rs - rt`. Execute returns `{ aluResult: rsVal - rtVal, writeReg: rd, writeData: rsVal - rtVal }`.
3. **ADDI** (I-type): `rt = rs + immediate`. Execute returns `{ aluResult: rsVal + imm, writeReg: rt, writeData: rsVal + imm }`. Note: ADDI writes to rt (not rd) in classic MIPS.
4. **LW** (I-type): `rt = memory[rs + immediate]`. Execute returns `{ aluResult: rsVal + imm, writeReg: rt, memRead: true }`. Memory access happens in MEM stage.
5. **SW** (S-type): `memory[rs + immediate] = rt`. Execute returns `{ aluResult: rsVal + imm, writeData: rtVal, memWrite: true }`. No register write.
6. **BEQ** (B-type): If `rs == rt`, branch to `PC + immediate * 4`. Execute returns `{ zero: rsVal === rtVal, branchTarget: pc + imm * 4 }`.
7. **J** (J-type): Jump to `immediate * 4` (absolute address). Execute returns `{ jumpTarget: imm * 4 }`.
8. **NOP** (Special): No operation. Execute returns `{}`. Used for pipeline bubbles and padding.

**Helper functions:**
- `InstructionSet.get(mnemonic)`: Returns instruction definition by mnemonic string.
- `InstructionSet.isMemoryInstruction(mnemonic)`: Returns true for LW, SW.
- `InstructionSet.isBranch(mnemonic)`: Returns true for BEQ, J.
- `InstructionSet.writesToRegister(mnemonic)`: Returns true for ADD, SUB, ADDI, LW (instructions that write back).

**Instruction factory function:**
- `InstructionSet.createInstruction(mnemonic, fields)`: Creates a concrete instruction object from mnemonic + field values. Example: `InstructionSet.createInstruction('ADD', { rs: 8, rt: 9, rd: 10 })` returns `{ mnemonic: 'ADD', type: 'R', rs: 8, rt: 9, rd: 10, immediate: 0 }`.

Export via `window.InstructionSet = InstructionSet;`. Wrap in IIFE.

All arithmetic should use 32-bit unsigned wrapping via `>>> 0` (or `| 0` for signed) to match Uint32Array behavior.
