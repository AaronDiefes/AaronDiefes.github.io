**Breadcrumbs:** Home > CPU Simulator > Documentation > Hazards & Forwarding

**Header:** Title "Hazards & Forwarding", subtitle "Checkpoint 4 - Keeping the Pipeline Flowing"

**Content sections:**

1. **Overview** - What are pipeline hazards:
   - Hazards are situations where the next instruction cannot execute in the next clock cycle
   - Three types: data hazards, control hazards, structural hazards
   - This processor primarily handles data hazards and control hazards
   - Without hazard handling: incorrect results (reading stale register values)
   - Solutions: forwarding (bypass), stalling (pipeline bubbles), flushing

2. **Data Hazards** - Read-After-Write (RAW) dependencies:
   - Occurs when an instruction needs a value that a previous instruction has not yet written back
   - Example scenario using the instruction timeline:
     ```
     add $1, $2, $3    // writes $1 in WB (cycle 5)
     sub $4, $1, $5    // reads $1 in ID (cycle 3) - STALE VALUE!
     ```
   - Without forwarding: the sub instruction reads the OLD value of $1
   - Show a timeline diagram (using CSS grid similar to pipeline page):
     ```
     Cycle:    1    2    3    4    5
     add $1:   IF   ID   EX   MEM  WB  <-- $1 written here
     sub $4:        IF   ID   EX   MEM <-- $1 read here (too early!)
     ```

   Use colored cells to highlight the conflict.

3. **Data Forwarding (Bypassing)** - The primary solution:
   - Instead of waiting for WB, forward the result from where it is computed
   - EX-to-EX forwarding: forward ALU result from EX/MEM register to EX stage input
   - MEM-to-EX forwarding: forward data from MEM/WB register to EX stage input
   - Forwarding MUX at ALU inputs selects between: register file output, EX/MEM forwarded value, MEM/WB forwarded value

   Verilog snippet for forwarding detection:
   ```verilog
   // Forwarding unit - detect EX hazard
   wire ex_hazard_A = (exmem_regWrite && exmem_rd != 0)
                    && (exmem_rd == idex_rs);
   wire ex_hazard_B = (exmem_regWrite && exmem_rd != 0)
                    && (exmem_rd == idex_rt);

   // Forwarding unit - detect MEM hazard
   wire mem_hazard_A = (memwb_regWrite && memwb_rd != 0)
                     && !(exmem_regWrite && exmem_rd == idex_rs)
                     && (memwb_rd == idex_rs);
   wire mem_hazard_B = (memwb_regWrite && memwb_rd != 0)
                     && !(exmem_regWrite && exmem_rd == idex_rt)
                     && (memwb_rd == idex_rt);
   ```

   Verilog snippet for forwarding MUX:
   ```verilog
   // Forwarding MUX for ALU input A
   wire [31:0] alu_input_a;
   assign alu_input_a = ex_hazard_A  ? exmem_alu_result :
                        mem_hazard_A ? wb_data :
                        data_readRegA;

   // Forwarding MUX for ALU input B
   wire [31:0] alu_input_b;
   assign alu_input_b = ex_hazard_B  ? exmem_alu_result :
                        mem_hazard_B ? wb_data :
                        data_readRegB;
   ```

4. **Load-Use Hazard (Stall Required)** - When forwarding is not enough:
   - Load instructions (lw) produce data in MEM stage, not EX stage
   - If the very next instruction needs the loaded value, we must stall 1 cycle
   - Example:
     ```
     lw  $1, 0($2)    // data available after MEM (cycle 4)
     add $3, $1, $4    // needs $1 in EX (cycle 3) - NOT READY!
     ```
   - Solution: insert a pipeline bubble (NOP) and stall IF/ID register for 1 cycle
   - After the stall, forwarding from MEM/WB can resolve the dependency

   Verilog snippet for stall detection:
   ```verilog
   // Load-use hazard detection
   wire load_use_hazard = idex_memRead
                        && ((idex_rt == ifid_rs) || (idex_rt == ifid_rt));

   // Stall: freeze PC and IF/ID register, insert NOP in ID/EX
   assign stall = load_use_hazard;
   ```

5. **Control Hazards** - Branches and jumps:
   - Branch instructions (beq, bne) change program flow
   - The branch decision is made in EX stage, but instructions are already fetched
   - Wrong-path instructions must be flushed from the pipeline
   - This processor flushes 2 instructions (IF and ID stages) on a taken branch
   - Jump instructions (j, jal) always flush 1 instruction

   Verilog snippet for flush logic:
   ```verilog
   // Branch resolution in EX stage
   wire branch_taken = ctrl_branch && (ctrl_bne ? alu_neq : ~alu_neq);
   wire jump = ctrl_jump;

   // Flush IF/ID and ID/EX on taken branch or jump
   assign flush_ifid = branch_taken || jump;
   assign flush_idex = branch_taken;

   // PC source selection
   assign pc_next = jump        ? jump_target :
                    branch_taken ? branch_target :
                    pc_plus_one;
   ```
