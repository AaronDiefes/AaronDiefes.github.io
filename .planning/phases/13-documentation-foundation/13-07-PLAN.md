1. **Overview** - Instruction encoding:
   - 32-bit fixed-width instructions
   - Three instruction formats: R-type, I-type, J-type
   - Opcode is always bits [31:27] (5 bits)
   - The processor implements a subset of the MIPS-like ISA used in ECE 350


**Breadcrumbs:** Home > CPU Simulator > Documentation > Memory System

**Header:** Title "Memory System", subtitle "Instruction and Data Memory"

**Content sections:**

1. **Overview** - Memory in the processor:
   - Harvard architecture: separate instruction memory (ROM) and data memory (RAM)
   - Instruction memory is read-only (loaded with program at synthesis)
   - Data memory is read/write (for load and store instructions)
   - Both memories are word-addressed (32-bit words)
   - Memory address space: 12-bit addresses (4096 words)

2. **Instruction Memory (ROM)** - Read-only program storage:
   - Contains the assembled program binary
   - Addressed by the Program Counter (PC)
   - Combinational read (no clock delay): instruction available same cycle as address
   - In simulation: initialized from a .mem or .mif file
   - In synthesis: compiled into FPGA block RAM

   Verilog snippet:
   ```verilog
   // Instruction Memory (ROM)
   module ROM(
     input [11:0] address,
     output [31:0] data
   );
     reg [31:0] memory [0:4095];

     initial begin
       $readmemh("program.mem", memory);
     end

     assign data = memory[address];
   endmodule
   ```

3. **Data Memory (RAM)** - Read/write data storage:
   - Used by load (lw) and store (sw) instructions
   - Synchronous write: data written on clock edge
   - Combinational read: data available same cycle (or synchronous with 1-cycle latency)
   - Write enable controlled by the memory stage

   Verilog snippet:
   ```verilog
   // Data Memory (RAM)
   module RAM(
     input [11:0] address,
     input [31:0] data_in,
     input write_enable,
     input clock,
     output [31:0] data_out
   );
     reg [31:0] memory [0:4095];

     always @(posedge clock) begin
       if (write_enable)
         memory[address] <= data_in;
     end

     assign data_out = memory[address];
   endmodule
   ```

4. **Memory Map** - Address space layout:
   - Table showing:
     - 0x000 - 0xFFF: Instruction Memory (ROM) - 4096 words
     - 0x000 - 0xFFF: Data Memory (RAM) - 4096 words (separate address space)
   - Harvard architecture means separate address buses
   - No memory-mapped I/O in this design

5. **Wrapper Module** - Top-level connection:
   - The `Wrapper.v` module connects processor, ROM, and RAM
   - Processor outputs memory addresses and data
   - Wrapper routes signals to appropriate memory modules
   - Clock and reset distributed from wrapper

   Verilog snippet:
   ```verilog
   // Top-level Wrapper connecting processor to memories
   module Wrapper(
     input clock, reset
   );
     wire [31:0] instruction, pc;
     wire [31:0] mem_address, mem_data_in, mem_data_out;
     wire mem_write_enable;

     // Instruction Memory
     ROM imem(.address(pc[11:0]), .data(instruction));

     // Data Memory
     RAM dmem(
       .address(mem_address[11:0]),
       .data_in(mem_data_in),
       .write_enable(mem_write_enable),
       .clock(clock),
       .data_out(mem_data_out)
     );

     // Processor
     processor cpu(
       .clock(clock), .reset(reset),
       .instruction(instruction),
       .pc(pc),
       .mem_address(mem_address),
       .mem_data_in(mem_data_in),
       .mem_data_out(mem_data_out),
       .mem_write_enable(mem_write_enable)
     );
   endmodule
   ```

6. **Memory in the Simulator** - How the JavaScript demo models memory:
   - Instruction memory: array of instruction objects with opcode/operand fields
   - Data memory: Uint32Array of 256 words (simplified from 4096)
   - Memory view component shows non-zero addresses
   - Link to the CPU simulator demo (/projects/cpu-simulator)

   - Try the Simulator: /projects/cpu-simulator
   - GitHub: https://github.com/AaronDiefes/CPU
