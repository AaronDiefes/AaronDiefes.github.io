**Header:** Title "Register File", subtitle "Checkpoint 2 - 32-Register Storage"

**Content sections:**

1. **Overview** - What the register file does:
   - Provides fast-access storage for the processor's working data
   - 32 registers, each 32 bits wide (named $0 through $31)
   - Two read ports (simultaneous reads) and one write port
   - Clock-synchronized writes, combinational reads
   - $0 is hardwired to zero (reads always return 0, writes are ignored)

2. **Architecture** - Design of the register file:
   - 32x32-bit register array
   - Two 5-bit read address inputs (ctrl_readRegA, ctrl_readRegB)
   - Two 32-bit read data outputs (data_readRegA, data_readRegB)
   - One 5-bit write address input (ctrl_writeReg)
   - One 32-bit write data input (data_writeReg)
   - Write enable signal (ctrl_writeEnable)
   - Clock input for synchronous writes

   Include a diagram-like section showing the register file ports:
   ```
   Inputs:                      Outputs:
   ctrl_readRegA [4:0]  -----> data_readRegA [31:0]
   ctrl_readRegB [4:0]  -----> data_readRegB [31:0]
   ctrl_writeReg [4:0]
   data_writeReg [31:0]
   ctrl_writeEnable
   clock
   ```

3. **$0 Hardwired to Zero** - Why and how:
   - Convention in RISC ISAs: register $0 always reads as 0
   - Useful for comparisons, moves, and as a discard target
   - Implementation: write-enable decoder skips register 0
   - Read mux returns constant 0 when address is 0

   Verilog snippet:
   ```verilog
   // Register $0 hardwired to zero
   // Write enable for each register (skip $0)
   genvar i;
   generate
     for (i = 1; i < 32; i = i + 1) begin: reg_loop
       register_32 reg_i(.d(data_writeReg), .clk(clock), .en(write_en[i]),
                         .clr(ctrl_reset), .q(reg_out[i]));
     end
   endgenerate

   // $0 always outputs zero
   assign reg_out[0] = 32'b0;
   ```

4. **Read Port Implementation** - How reads work:
   - Combinational (no clock delay) for read-after-write in same cycle
   - Uses 32:1 multiplexer to select from register array
   - Two independent read ports allow reading two registers simultaneously
   - This enables R-type instructions that need two source operands

   Verilog snippet:
   ```verilog
   // 32:1 mux for read port A
   assign data_readRegA = reg_out[ctrl_readRegA];

   // 32:1 mux for read port B
   assign data_readRegB = reg_out[ctrl_readRegB];
   ```

5. **Write Port Implementation** - How writes work:
   - Synchronous: data written on positive clock edge
   - Write enable decoder: only the selected register gets write pulse
   - One write port (limitation: only one register written per cycle)

   Verilog snippet:
   ```verilog
   // Write enable decoder - one-hot encoding
   wire [31:0] write_en;
   decoder_5to32 write_decoder(
     .in(ctrl_writeReg),
     .enable(ctrl_writeEnable),
     .out(write_en)
   );
   ```

6. **Register Conventions** - Common register usage in MIPS:
   - Table showing: $0 (zero), $1 ($at - assembler temp), $2-$3 ($v0-$v1 - return values), $4-$7 ($a0-$a3 - arguments), $8-$15 ($t0-$t7 - temporaries), $16-$23 ($s0-$s7 - saved), $29 ($sp - stack pointer), $31 ($ra - return address)

7. **Explore Further** - Quick links:
   - Previous: ALU Design (/cpu-docs/alu)
   - Next: Multiplication & Division (/cpu-docs/multdiv)
   - Back to CPU docs (/cpu-docs)
   - GitHub: https://github.com/AaronDiefes/CPU
