**Breadcrumbs:** Home > CPU Simulator > Documentation > Pipeline Architecture

**Header:** Title "Pipeline Architecture", subtitle "Checkpoint 4 - 5-Stage Pipelined Processor"

**Content sections:**

1. **Overview** - What pipelining is:
   - Without pipelining: each instruction takes 5 cycles to complete before the next starts
   - With pipelining: multiple instructions overlap in different stages simultaneously
   - Ideal throughput: 1 instruction completed per clock cycle (5x speedup)
   - The processor uses 5 stages: Fetch, Decode, Execute, Memory, Writeback
   - Pipeline registers between each stage hold intermediate results

2. **Pipeline Stages** - Detailed explanation of each stage. Use the `.pipeline-diagram` / `.pipeline-step` CSS from the landing page to create a visual pipeline flow at the top. Then explain each stage in detail:

   **Stage 1: Instruction Fetch (IF)**
   - Reads instruction from instruction memory (ROM) using Program Counter (PC)
   - Increments PC by 1 for next instruction (or uses branch/jump target)
   - Passes instruction and PC+1 to IF/ID pipeline register

   Verilog snippet:
   ```verilog
   // Instruction Fetch stage
   wire [31:0] pc_current, pc_plus_one, instruction;

   assign pc_plus_one = pc_current + 32'd1;

   // Instruction memory (ROM)
   ROM instruction_memory(
     .address(pc_current[11:0]),
     .data(instruction)
   );
   ```

   **Stage 2: Instruction Decode (ID)**
   - Decodes the instruction fields: opcode, rs, rt, rd, shamt, funct, immediate
   - Reads two source registers from the register file
   - Sign-extends the 16-bit immediate value to 32 bits
   - Control unit generates control signals based on opcode

   Verilog snippet:
   ```verilog
   // Instruction Decode - field extraction
   wire [4:0]  opcode = instruction[31:27];
   wire [4:0]  rd     = instruction[26:22];
   wire [4:0]  rs     = instruction[21:17];
   wire [4:0]  rt     = instruction[16:12];
   wire [4:0]  shamt  = instruction[11:7];
   wire [16:0] immediate = instruction[16:0];
   wire [26:0] target = instruction[26:0];

   // Sign extension
   wire [31:0] sign_extended = {{15{immediate[16]}}, immediate};
   ```

   **Stage 3: Execute (EX)**
   - ALU performs computation (add, subtract, compare, etc.)
   - For R-type: ALU operates on two register values
   - For I-type: ALU operates on one register and sign-extended immediate
   - For branches: ALU computes branch condition (equal/not-equal)
   - MultDiv unit handles multiply and divide operations

   Verilog snippet:
   ```verilog
   // Execute stage - ALU input selection
   wire [31:0] alu_inputA = data_readRegA;
   wire [31:0] alu_inputB = ctrl_ALUinB ? sign_extended : data_readRegB;

   ALU processor_alu(
     .data_operandA(alu_inputA),
     .data_operandB(alu_inputB),
     .ctrl_ALUopcode(alu_opcode),
     .ctrl_shiftamt(shamt),
     .data_result(alu_result),
     .isNotEqual(alu_neq),
     .isLessThan(alu_lt),
     .overflow(alu_overflow)
   );
   ```

   **Stage 4: Memory Access (MEM)**
   - Load instructions read from data memory (RAM)
   - Store instructions write to data memory (RAM)
   - Other instructions pass through (ALU result forwarded to next stage)
   - Memory address comes from ALU result

   Verilog snippet:
   ```verilog
   // Memory stage
   RAM data_memory(
     .address(alu_result_mem[11:0]),
     .data_in(data_readRegB_mem),
     .write_enable(ctrl_memWrite),
     .clock(clock),
     .data_out(mem_data)
   );

   // Select: memory data (load) or ALU result (other)
   wire [31:0] wb_data = ctrl_memToReg ? mem_data : alu_result_mem;
   ```

   **Stage 5: Write Back (WB)**
   - Writes the result back to the register file
   - Destination register comes from rd (R-type) or rt (I-type loads)
   - Write enable asserted for instructions that produce a result
   - Connects back to the register file write port

   Verilog snippet:
   ```verilog
   // Write Back stage
   assign ctrl_writeEnable = reg_write_wb;
   assign ctrl_writeReg = dest_reg_wb;
   assign data_writeReg = wb_data_wb;
   ```

3. **Pipeline Registers** - The glue between stages:
   - IF/ID register: holds instruction and PC+1
   - ID/EX register: holds decoded values, control signals, register data
   - EX/MEM register: holds ALU result, memory write data, control signals
   - MEM/WB register: holds final data to write back, control signals
   - All pipeline registers are edge-triggered D flip-flops
   - Flush and stall control for hazards

   Verilog snippet:
   ```verilog
   // IF/ID Pipeline Register
   reg [31:0] ifid_instruction, ifid_pc_plus_one;

   always @(posedge clock or posedge reset) begin
     if (reset || flush_ifid) begin
       ifid_instruction <= 32'b0;  // NOP
       ifid_pc_plus_one <= 32'b0;
     end else if (!stall) begin
       ifid_instruction <= instruction;
       ifid_pc_plus_one <= pc_plus_one;
     end
   end
   ```

4. **Control Unit** - Generating control signals:
   - Opcode-based decoding: each opcode maps to a set of control signals
   - Control signals: RegWrite, MemWrite, MemToReg, ALUSrc, Branch, Jump, ALUOp
   - Table of control signals per instruction type:
     - R-type (00000): RegWrite=1, ALUSrc=0
     - addi (00101): RegWrite=1, ALUSrc=1
     - lw (01000): RegWrite=1, MemToReg=1, ALUSrc=1
     - sw (00111): MemWrite=1, ALUSrc=1
     - beq (00010): Branch=1
     - bne (00110): Branch=1
     - j (00001): Jump=1
     - jal (00011): RegWrite=1, Jump=1
