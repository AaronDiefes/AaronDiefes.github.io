**Header:** Title "Multiplication & Division", subtitle "Checkpoint 3 - Multi-Cycle Arithmetic"

**Content sections:**

1. **Overview** - Why MultDiv is complex:
   - Multiplication and division cannot be done in a single clock cycle
   - These are multi-cycle operations (16 cycles for 32-bit multiply)
   - The MultDiv unit operates independently from the main pipeline
   - Uses a ready signal to indicate when the result is available
   - Processor stalls while waiting for MultDiv to complete

2. **Modified Booth's Algorithm** - How multiplication works:
   - Standard multiplication: shift-and-add (32 cycles for 32-bit)
   - Booth's encoding: examines pairs of multiplier bits to reduce partial products
   - Modified Booth (radix-4): examines 3 bits at a time, processes 2 bits per cycle
   - Reduces 32 cycles to 16 cycles (2-layer)
   - Encoding table:
     - 000 -> +0 (no operation)
     - 001 -> +M (add multiplicand)
     - 010 -> +M (add multiplicand)
     - 011 -> +2M (shift and add)
     - 100 -> -2M (shift and subtract)
     - 101 -> -M (subtract multiplicand)
     - 110 -> -M (subtract multiplicand)
     - 111 -> +0 (no operation)

   Verilog snippet for Booth encoding:
   ```verilog
   // Modified Booth encoding - examine 3 bits of multiplier
   wire [2:0] booth_bits;
   assign booth_bits = {multiplier[i+1], multiplier[i], multiplier[i-1]};

   // Partial product selection based on Booth encoding
   always @(*) begin
     case(booth_bits)
       3'b000, 3'b111: partial_product = 64'b0;        // +0
       3'b001, 3'b010: partial_product = multiplicand;  // +M
       3'b011:         partial_product = multiplicand << 1; // +2M
       3'b100:         partial_product = ~(multiplicand << 1) + 1; // -2M
       3'b101, 3'b110: partial_product = ~multiplicand + 1; // -M
     endcase
   end
   ```

3. **Multiplication State Machine** - How the multi-cycle operation works:
   - IDLE state: waiting for multiply command
   - RUNNING state: iterating through Booth's algorithm (16 cycles)
   - DONE state: result ready, assert data_resultRDY
   - The accumulator register holds the running sum of partial products
   - Each cycle: shift multiplier right by 2, add/subtract partial product

   Verilog snippet for the state machine:
   ```verilog
   // MultDiv state machine
   reg [4:0] counter;
   reg [1:0] state; // 0=IDLE, 1=MULTIPLY, 2=DIVIDE, 3=DONE

   always @(posedge clock or posedge reset) begin
     if (reset) begin
       state <= 2'b00;
       counter <= 5'b0;
       data_resultRDY <= 1'b0;
     end else begin
       case(state)
         2'b00: begin // IDLE
           if (ctrl_MULT) begin
             state <= 2'b01;
             counter <= 5'd16;
             // Initialize accumulator and multiplier
           end
         end
         2'b01: begin // MULTIPLY
           if (counter == 0) begin
             state <= 2'b11; // DONE
             data_resultRDY <= 1'b1;
           end else begin
             counter <= counter - 1;
             // Apply Booth's encoding, accumulate partial product
           end
         end
       endcase
     end
   end
   ```

4. **Division Algorithm** - Restoring division:
   - Uses restoring division algorithm (shift-and-subtract)
   - Takes 32 cycles to produce quotient and remainder
   - Each cycle: shift remainder left, subtract divisor, check sign
   - If remainder negative, restore (add divisor back) and quotient bit = 0
   - If remainder positive, keep and quotient bit = 1
   - Handles signed division with pre/post sign correction

   Verilog snippet:
   ```verilog
   // Restoring division - one iteration
   // Shift remainder left, subtract divisor
   wire [31:0] shifted_remainder = {remainder[30:0], dividend[31-i]};
   wire [31:0] trial = shifted_remainder - divisor;

   // If trial >= 0, keep subtraction; otherwise restore
   assign remainder_next = trial[31] ? shifted_remainder : trial;
   assign quotient[31-i] = ~trial[31];
   ```

5. **Exception Handling** - Division by zero and overflow:
   - Division by zero: detected before starting, sets exception flag
   - Overflow: multiplication result exceeds 32 bits (use upper 32 bits for detection)
   - Exception signal (data_exception) raised to processor

6. **Integration with Pipeline** - How MultDiv connects:
   - Stalls pipeline when MultDiv is busy (data_resultRDY = 0)
   - Multiply result: lower 32 bits of 64-bit product
   - Divide result: quotient (32-bit)
   - Uses the ALU's adder for the shift-and-add operations
