**Content sections (6 total):**

1. **Overview Section:**
   - Explain the ride-sharing matching problem: given a set of riders and available drivers, find the optimal rider-driver matches
   - Two key metrics: D1 (average match distance) and D2 (maximum match distance)
   - Progressive optimization approach: each iteration improves upon the previous
   - Brief summary of T1-T5 with complexity listed

2. **T1: Brute Force Section:**
   - Explain: Check every driver for every rider, compute distance, keep minimum
   - Complexity badge: O(n * m)
   - Python code block with syntax highlighting showing `match_brute_force(riders, drivers)` function:
     - Iterate over all riders, for each rider iterate over all drivers
     - Compute Euclidean distance: `sqrt((r.lat - d.lat)**2 + (r.lon - d.lon)**2)`
     - Track minimum distance and best driver
     - Return list of (rider, driver) matches
   - Inline annotations: explain what each key line does using `<span className="comment">` tags
   - Performance note: Simple but O(n*m), impractical for large datasets

3. **T2: Sorted Distance Optimization Section:**
   - Explain: Pre-sort drivers by one coordinate axis, use early termination
   - Complexity badge: O(n * m) worst case, O(n * m/k) average with pruning
   - Python code block showing sorted-driver approach with early exit:
     - Sort drivers by latitude
     - For each rider, only check drivers within a distance threshold
     - Break early when sorted coordinate exceeds threshold
   - Inline annotations explaining the pruning optimization
   - Performance note: Same worst case but faster average case

4. **T3: Grid-Based Spatial Partitioning Section:**
   - Explain: Divide the area into grid cells, only search nearby cells
   - Complexity badge: O(n * k) where k = drivers per cell
   - Python code block showing grid partitioning:
     - Create grid cells based on coordinate ranges
     - Assign drivers to cells by lat/lon
     - For each rider, search only nearby cells (3x3 neighborhood)
   - Inline annotations explaining grid cell calculation
   - Performance note: Major improvement but grid granularity is fixed

5. **T4: KD-Tree Nearest Neighbor Section:**
   - Explain: Use KD-tree for O(log n) nearest-neighbor queries
   - Complexity badge: O(n * log m)
   - Python code block showing KD-tree construction and query:
     - Build KD-tree from driver locations
     - For each rider, query tree for nearest driver
     - Mark matched drivers as unavailable
   - Inline annotations explaining tree query vs brute force
   - Note: Links to full KD-Tree documentation page (`/projects/cs330/docs/kdtree`)

6. **T5: KD-Tree + Dijkstra Road Network Section:**
   - Explain: Combine spatial indexing with road-network distance (not Euclidean)
   - Complexity badge: O(n * (log m + E log V))
   - Python code block showing combined approach:
     - KD-tree finds k nearest candidate drivers (Euclidean)
     - Dijkstra computes actual road distances for candidates
     - Select driver with shortest road distance
   - Inline annotations explaining why road distance differs from Euclidean
   - Note: Links to full Pathfinding documentation page (`/projects/cs330/docs/pathfinding`)
