  <name>Task 1: Create BlockDiagramView SVG component</name>
  <files>cpu-simulator/src/visualization/block-diagram-view.js</files>
  <action>
Create a new `BlockDiagramView` class in an IIFE wrapper (matching existing Phase 9/10 module pattern with `window.BlockDiagramView` export).

**Constructor:** Takes a container element. Creates the root SVG element with `viewBox="0 0 900 500"` and `preserveAspectRatio="xMidYMid meet"`. Builds the complete diagram by appending layers in painter's order (back-to-front): data paths first, then components, then pipeline registers, then labels/text.

**SVG Helper:** Create a private `_svg(tagName, attributes)` method that wraps `document.createElementNS('http://www.w3.org/2000/svg', tagName)` and sets all attributes via `setAttribute()`. Use this for ALL SVG element creation.

**Component Layout (left-to-right, matching Duke ECE 350 Slide 09 reference):**

The diagram should flow left-to-right through the 5 pipeline stages:

1. **IF Stage (x: 20-150):**
   - PC block: small rect at far left (x:20, y:220, w:60, h:40), label "PC"
   - Adder: small rect below PC (x:20, y:280, w:60, h:30), label "+4"
   - Instruction Memory: larger rect (x:100, y:150, w:120, h:180), label "Instruction\nMemory" (use two `<tspan>` elements for line break)
   - Data attributes: `data-component="PC"`, `data-component="ADDER"`, `data-component="IMEM"`

2. **Pipeline Register F/D (x: 235-243):**
   - Vertical red bar (x:235, y:80, w:8, h:340)
   - Label "F/D" above bar
   - Instruction text below bar (updated dynamically), `data-instruction-display="FD"`

3. **ID Stage (x: 260-400):**
   - Register File: larger rect (x:270, y:130, w:120, h:220), label "Register\nFile"
   - Sign Extend: small rect below (x:290, y:380, w:80, h:35), label "Sign\nExtend"
   - Data attributes: `data-component="REGFILE"`, `data-component="SIGNEXT"`

4. **Pipeline Register D/X (x: 415-423):**
   - Same red bar pattern as F/D
   - Label "D/X", instruction text, `data-instruction-display="DX"`

5. **EX Stage (x: 440-560):**
   - ALU Src Mux: blue triangle (polygon) before ALU, pointing right
   - ALU: rect with slightly rounded corners (x:480, y:170, w:80, h:120), label "ALU"
   - Data attributes: `data-component="ALU"`, `data-mux="ALU_SRC"`

6. **Pipeline Register X/M (x: 575-583):**
   - Same red bar pattern
   - Label "X/M", instruction text, `data-instruction-display="XM"`

7. **MEM Stage (x: 600-720):**
   - Data Memory: larger rect (x:610, y:150, w:120, h:180), label "Data\nMemory"
   - Data attribute: `data-component="DMEM"`

8. **Pipeline Register M/W (x: 735-743):**
   - Same red bar pattern
   - Label "M/W", instruction text, `data-instruction-display="MW"`

9. **WB Stage (x: 760-880):**
   - WB Mux: blue triangle selecting between memory data and ALU result for write-back
   - Data attribute: `data-mux="WB_SRC"`

**Multiplexers (blue triangles):** Create using `<polygon>` with 3 vertices forming a rightward-pointing triangle. Place at:
- Before ALU (ALU source selection: register vs immediate)
- At WB stage (write-back data selection: ALU result vs memory data)
- Before PC (PC source selection: PC+4 vs branch/jump target)

**Data Path Wires:** Create using `<line>` or `<path>` elements with class `data-path`. Draw connections between:
- PC output -> Instruction Memory input
- Adder output -> PC input (feedback loop for PC+4)
- Instruction Memory output -> F/D register
- F/D -> Register File (read registers)
- F/D -> Sign Extend
- Register File outputs -> D/X register
- D/X -> ALU Src Mux -> ALU
- ALU output -> X/M register
- X/M -> Data Memory (address/write data)
- Data Memory output -> M/W register
- M/W -> WB Mux -> Register File (write back, long line going back)
Keep wires simple - straight horizontal/vertical lines with right-angle turns. Use class `data-path` for styling. NO value labels on wires (user decision).

**Tooltips:** Add a `<title>` child element inside each component `<g>` group with a short description:
- PC: "Program Counter - Holds address of current instruction"
- Instruction Memory: "Instruction Memory - Stores program instructions"
- Register File: "Register File - 32 general-purpose registers"
- ALU: "Arithmetic Logic Unit - Performs computations"
- Data Memory: "Data Memory - Read/write data storage"
- F/D: "Fetch/Decode Register - Holds instruction between IF and ID stages"
- etc.

**Grouping:** Wrap each component in a `<g>` element with:
- `class="component {type}"` (e.g., `class="component alu"`, `class="component instruction-memory"`)
- `data-component="{TYPE}"` for JavaScript selection
- Pipeline registers get `class="pipeline-register"` and `data-pipeline-reg="{FD|DX|XM|MW}"`
- Muxes get `class="multiplexer"` and `data-mux="{name}"`

**render(state) method:**
1. Clear all active states: `querySelectorAll('.component.active, .multiplexer.active').forEach(el => el.classList.remove('active'))`
2. Check each pipeline stage's `active` flag in `state.pipeline`:
   - IF active -> highlight IMEM, PC components
   - ID active -> highlight REGFILE, SIGNEXT components
   - EX active -> highlight ALU, ALU_SRC mux
   - MEM active -> highlight DMEM (only if memRead or memWrite is true)
   - WB active -> highlight WB_SRC mux
3. Update pipeline register instruction displays by querying `[data-instruction-display]` elements:
   - Map: FD <- IF stage, DX <- ID stage, XM <- EX stage, MW <- MEM stage
   - If stage is active and has instruction (from `state.pipeline.IF.instruction` in non-pipelined mode), display formatted instruction using `_formatInstruction()`
   - Otherwise display 'NOP'
4. The `_formatInstruction(instruction)` method should format identically to the existing PipelineView.formatOperands pattern: R-type `ADD $rd, $rs, $rt`, I-type `ADDI $rt, $rs, imm`, load `LW $rt, imm($rs)`, store `SW $rt, imm($rs)`, branch `BEQ $rs, $rt, offset`, jump `J target`

**Text rendering notes (from RESEARCH.md pitfalls):**
- Use `text-anchor="middle"` for centered text within components
- Use `dominant-baseline="middle"` for vertical centering
- For multi-line labels use `<tspan>` elements with `dy` offsets (NOT `\n` in textContent)
- Pipeline instruction text uses small monospace font (11-12px)
- Component labels use 13-14px regular font

**Important constraints from user decisions:**
- SVG-based rendering (NOT canvas or HTML/CSS positioned elements)
- NO value labels on data path wires
- Tooltips via native `<title>` elements (NOT custom JS tooltip library)
- Color scheme should complement existing forest green theme (Claude's discretion on exact colors)
