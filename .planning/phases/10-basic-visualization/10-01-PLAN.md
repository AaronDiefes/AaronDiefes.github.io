<task type="auto">
  <name>Task 2: Create PipelineView component for 5-stage pipeline visualization</name>
  <files>cpu-simulator/src/visualization/pipeline-view.js</files>
  <action>
Create `cpu-simulator/src/visualization/pipeline-view.js` wrapped in IIFE with `window.PipelineView` export (matches Phase 9 module pattern).

**PipelineView class:**

**Constructor(container):**
- Store `this.container = container`
- Create `this.stageElements = new Map()` for fast stage lookup
- Call `this.initializeStages()`

**initializeStages():**
- Define stage names: `['IF', 'ID', 'EX', 'MEM', 'WB']`
- Define full names map: `{ IF: 'Instruction Fetch', ID: 'Instruction Decode', EX: 'Execute', MEM: 'Memory Access', WB: 'Write Back' }`
- Create DocumentFragment for batch DOM insertion
- For each stage, create a div with:
  - `className = 'pipeline-stage'`
  - `dataset.stage = stageName`
  - innerHTML containing:
    ```html
    <div class="stage-header">
      <span class="stage-label">${stageName}</span>
      <span class="stage-name">${fullName}</span>
    </div>
    <div class="stage-content">
      <code class="instruction-text" data-stage-instruction>NOP</code>
    </div>
    ```
  - Store in `this.stageElements.set(stageName, stageCard)`
  - Append to fragment
- Append fragment to container (single DOM insertion)

**render(state):**
- Read `state.pipeline` object which has keys: IF, ID, EX, MEM, WB
- For each stage name in ['IF', 'ID', 'EX', 'MEM', 'WB']:
  - Get stage data from `state.pipeline[stageName]`
  - Get stage card from `this.stageElements.get(stageName)`
  - Get instruction element: `card.querySelector('[data-stage-instruction]')`
  - If `stageData.active === true`:
    - Get instruction from `stageData.instruction` (IF/ID stages have it directly)
    - Format display text: `${instruction.mnemonic} ${formatOperands(instruction)}` where formatOperands builds operand string from register numbers
    - Add 'active' class to card
  - Else:
    - Set instruction text to 'NOP'
    - Remove 'active' class from card

**formatOperands(instruction) helper (private):**
Create a static method or internal function that formats instruction operands for display:
- R-type (ADD, SUB): `$rd, $rs, $rt` → e.g., `$10, $8, $9`
- I-type (ADDI, LW, SW):
  - ADDI: `$rt, $rs, imm` → e.g., `$8, $0, 10`
  - LW: `$rt, imm($rs)` → e.g., `$12, 0($8)`
  - SW: `$rt, imm($rs)` → e.g., `$10, 0($8)`
- B-type (BEQ): `$rs, $rt, offset` → e.g., `$8, $8, 2`
- J-type (J): `target` → e.g., `0`
- NOP: empty string

Use instruction.type field ('R', 'I', 'S', 'B', 'J', 'NOP') to determine format. Use instruction.rs, instruction.rt, instruction.rd, instruction.immediate fields.

**Important data shape notes (from reading cpu-state.js and sequence-generator.js):**
- `state.pipeline.IF.instruction` is the instruction object (has .mnemonic, .type, .rs, .rt, .rd, .immediate) or null
- `state.pipeline.ID.instruction` is also stored during ID stage
- For EX/MEM/WB stages, the instruction is NOT directly stored on the stage object. However, the render function needs to show which instruction is in each stage.
- **Solution:** During non-pipelined execution (Phase 9), only ONE stage is active at a time (indicated by `.active = true`). The IF and ID stages store `.instruction`. For EX/MEM/WB, look back to `state.pipeline.ID.instruction` or `state.pipeline.IF.instruction` since the instruction propagates through stages within the same frame. Since the instruction originates in IF and is also stored in ID, and only one stage is active per frame, use `state.pipeline.IF.instruction` as the current instruction for ALL stages when that stage is active. This works because in non-pipelined mode, the same instruction flows through all 5 stages.

**File 1: cpu-simulator/src/visualization/register-view.js**

Create RegisterView class wrapped in IIFE with `window.RegisterView` export.

**Constructor(container):**
- Store `this.container = container`
- Create `this.registerCells = []` (array of 32 DOM elements for O(1) access by index)
- Call `this.initializeRegisters()`

**initializeRegisters():**
- Create DocumentFragment
- Loop i = 0 to 31:
  - Create div with `className = 'register-cell'`, `dataset.register = i`
  - innerHTML:
    ```html
    <span class="register-label">$${i}</span>
    <span class="register-value">0x00000000</span>
    ```
  - Push to `this.registerCells` array
  - Append to fragment
- Append fragment to container

**render(state):**
- **Selective update only** -- do NOT iterate all 32 registers every frame
- First, remove 'changed' class from any previously highlighted cells (track via `this._previousChanged` array, initially empty)
- Convert `state.changedRegisters` from Set to Array: `const changed = Array.from(state.changedRegisters || [])`
- For each register index in `changed`:
  - Get cell from `this.registerCells[index]`
  - Get value element: `cell.querySelector('.register-value')`
  - Update text: `'0x' + state.registers[index].toString(16).toUpperCase().padStart(8, '0')`
  - Add 'changed' class to cell
- Store `this._previousChanged = changed` for cleanup on next render call
- **Also update ALL register values on first render** (when `this._initialized` is false): Loop all 32 registers, set their value text, then set `this._initialized = true`. Subsequent renders only update changed registers.

**Edge case:** Register $0 should always show 0x00000000 even if changedRegisters includes 0 (it shouldn't due to setRegister protection, but be defensive).
